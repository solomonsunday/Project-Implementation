📋 Project Overview

This project builds a Zero Trust, Secure-by-Design Azure environment for a fintech workload. No implicit trust is granted to any user, device, or network segment — every access request is evaluated by Microsoft Entra ID before being permitted.

The Crown Jewel — an Azure SQL Database holding sensitive financial records — has no public internet exposure. It is reachable only through a Private Endpoint inside a dedicated subnet, with NSG micro-segmentation controlling which subnets can initiate a connection to it.

Requirement 1

Architectural Design

Hub-and-Spoke topology with centralised PDP (Entra ID) and distributed PEPs (NSGs). Crown Jewel protected by Private Link and micro-segmentation.

Requirement 2

Development Environment

Full Infrastructure-as-Code using Terraform. Components: Entra ID, Intune, Azure Bastion, Microsoft Sentinel — all codified and reproducible.

📦 Terraform Module Structure

The project follows a modular pattern — each infrastructure concern is encapsulated in its own module, enabling independent testing and reuse.

fintech-hub-spoke/
├── main.tf                  # Root module — wires modules together with explicit depends_on
├── providers.tf             # azurerm ~> 3.117, azuread, random, null, time
├── variables.tf             # location, environment, project, credentials
├── terraform.tfvars         # westeurope, dev, fintech (gitignored)
├── outputs.tf               # Bastion IP, VNet IDs, SQL FQDN, Sentinel workspace ID
├── run-apply.ps1            # terraform apply -auto-approve -parallelism=5
└── modules/
    ├── networking/          # Hub VNet, Spoke VNet, Subnets, NSGs, Peering
    ├── bastion/             # Azure Bastion Host + Public IP
    ├── compute/             # IT Admin VM + User VM + NICs + Finance Managed Identity
    ├── database/            # SQL Server, Database, Private Endpoint, DNS Zone
    ├── sentinel/            # Log Analytics Workspace (random suffix) + Sentinel + 4 KQL Rules
    ├── identity/            # Entra ID Conditional Access + Named Locations (5 policies)
    └── intune/              # Device Compliance Policy via Microsoft Graph API

Module Dependency Chain

Sentinel deploys first (creates the Log Analytics workspace), then networking and all workload modules follow. This ordering prevents circular dependencies and ensures monitoring is active before workloads are deployed:

azurerm_resource_group
  └── time_sleep (30s — ARM propagation wait)
       ├── module.sentinel        (Log Analytics + Sentinel — deploys first)
       └── module.networking      (VNets, Subnets, NSGs, Peering — depends_on: sentinel)
            ├── module.bastion    (depends_on: networking)
            ├── module.compute    (depends_on: networking) — IT Admin VM + User VM
            └── module.database   (depends_on: networking + compute)
ℹ️
Subnets within the Spoke VNet are created sequentially (finance → user → itadmin → db) via chained depends_on inside the networking module. This is required because Azure locks the parent VNet resource during subnet write operations — parallel subnet creation causes transient 404 errors.

Azure Bastion — Sole Management Entry Point

Azure Bastion (SKU: Standard) is deployed in the Hub VNet's AzureBastionSubnet. It provides browser-based RDP/SSH access to VMs without exposing any public ports. Both the IT Admin VM and User VM have no public IP addresses — accessible only via Bastion tunnel.

Crown Jewel — Azure Private Link

The SQL Server's public network access is disabled. It is only reachable via its Private Endpoint at 10.1.4.4 within snet-db. A Private DNS Zone (privatelink.database.windows.net) resolves the server's FQDN to this private IP — so even internal clients use the private path.

🛡️ Zero Trust Implementation

The architecture implements all three Zero Trust pillars:

Verify Explicitly

Microsoft Entra ID — Centralised PDP

Every access request is evaluated against 5 Conditional Access policies. Named locations define trusted corporate IP ranges. Device compliance checked before granting access.

Least Privilege

NSG Micro-segmentation + Private Link

Each subnet has the minimum permissions needed. User subnet cannot reach Finance or DB. Finance can only reach DB on port 1433. SQL has zero public internet exposure.

Assume Breach

Microsoft Sentinel — Continuous Monitoring

4 KQL-based scheduled alert rules continuously monitor for IT admin privilege abuse, brute force attacks, risky sign-ins, and lateral movement attempts.

⚙️ Implementation Challenges & Fixes

A number of Azure and Terraform-specific issues came up during deployment. Each is documented here with the root cause and the fix applied.

VM Capacity Restrictions — uksouth region exhausted

Multiple D-series and B-series VM SKUs were unavailable in uksouth due to capacity restrictions. Fix: Migrated entire deployment to westeurope and used Standard_D2s_v3.

ARM API Eventual Consistency — VNet 404 during provisioning polling

The azurerm provider polls GET immediately after PUT, sometimes receiving 404 before the resource propagates. Fix: Added a time_sleep of 30s after resource group creation.

Parallel Subnet Creation — VNet Lock Conflicts

Azure locks a VNet during subnet write operations. Parallel subnet creation caused 404 conflicts. Fix: Enforced sequential subnet creation using chained depends_on (finance → user → itadmin → db).

Sentinel Alert Rules — Soft-Delete Workspace Conflict

Azure Log Analytics workspaces have a 14-day soft-delete period. Recreating with the same name caused GUID mismatch errors. Fix: Added random_id suffix to workspace name, guaranteeing uniqueness on every deploy.

Sentinel Alert Rules — Soft-Delete Rule ID Conflict

Previously deleted Sentinel rule IDs remained in soft-delete state, causing 409 Conflict on recreation. Fix: Bump version suffix on each redeploy — currently -v4. Increased Sentinel onboarding sleep to 120s.

Too Much Parallelism — ARM Rate Limiting

Default Terraform parallelism of 10 caused cascading failures. Fix: Reduced to -parallelism=5 in run-apply.ps1.

Entra ID Connector — Workspace Managed by M365 Defender

The Sentinel AAD data connector failed because M365 Defender controls it exclusively. Fix: Removed the connector resource — logs flow automatically via M365 Defender integration.

User Subnet VM Missing — PoC Gap

Initial Terraform only deployed the IT Admin VM. The lateral movement stress test requires a VM in the User subnet to simulate a hijacked account — using IT Admin VM would not accurately represent the test scenario. Fix: Added vm-user-dev (Standard_D2s_v3, 128GB OS disk) to the compute module in snet-user (10.1.2.x).

User VM OS Disk Size — Image Minimum Constraint

Initial disk size of 64GB was rejected — Windows Server 2022 image requires a minimum of 127GB. Fix: Changed disk_size_gb to 128 in the User VM resource.

Standard_B1s Not Available — Capacity Restriction in westeurope

Attempting to use Standard_B1s for the cost-optimised User VM failed with capacity restrictions in westeurope. Fix: Changed to Standard_D2s_v3, consistent with the IT Admin VM.

NSG Flow Logs Retired — Blocked Since June 30, 2025

Terraform flow log resources using azurerm_network_watcher_flow_log with network_security_group_id failed with NsgFlowLogCreationBlocked. Azure blocked new NSG flow log creation as part of their deprecation ahead of the September 30, 2027 retirement. Fix: Removed NSG flow log resources. The lateral movement test is evidenced by PowerShell probe output and NSG portal screenshots instead.

VNet Flow Logs — Not Supported in azurerm 3.117.1

Attempting to migrate to VNet flow logs (the NSG replacement) using target_resource_id on azurerm_network_watcher_flow_log failed — the azurerm 3.117.1 provider does not support this argument. Fix: Flow logs removed entirely. Upgrade to azurerm 4.x or use the AzAPI provider is documented as a future improvement.

Network Watcher — One Per Region Limit

Creating azurerm_network_watcher failed with NetworkWatcherCountLimitReached — Azure auto-creates a Network Watcher (NetworkWatcher_westeurope in NetworkWatcherRG) when VNets are deployed. Only one is allowed per subscription per region. Fix: Replaced the resource block with a data source referencing the auto-created watcher, with depends_on = [azurerm_virtual_network.spoke] to ensure it exists before the data source reads it.

Terraform Destroy Cycle — Stale State from Partial Apply

After failed flow log applies, the state contained orphaned azurerm_storage_account.flowlogs and random_id.flowlogs_suffix resources no longer in the configuration. This caused a cycle error during terraform destroy. Fix: Removed stale resources from state with terraform state rm before destroying.

Conditional Access — Insufficient Licensing

Conditional Access policies were deployed by Terraform but not visible in the portal — the subscription does not include Entra ID Premium P1. The policies exist in the API but cannot be managed or enforced without the license. Fix: Activate a 30-day Entra ID P2 free trial via Entra ID → Licenses → All products → Try/Buy.

Sentinel Incident Creation — incidentConfiguration Not Applied on First Deploy

The rule-risky-signin-v4 rule was firing and generating SecurityAlert entries, but no incidents appeared in the Sentinel Incidents blade. Inspecting the rule via az sentinel alert-rule show revealed the incidentConfiguration property was missing entirely — meaning the Terraform incident block was silently ignored by the azurerm 3.117.1 provider on the initial apply. Fix: Verified the incident { create_incident_enabled = true } block is present in modules/sentinel/main.tf (it was already there). The provider now applies it correctly on fresh deploys. If the issue recurs, use az rest --method PUT to force the property via the REST API.

Hardcoded Local Paths in PowerShell Scripts — Portability Fix

Both run-apply.ps1 and run-plan.ps1 contained a hardcoded absolute path (Set-Location "C:\Users\adewusi.akeem\fintech-hub-spoke") that would break for any other user who cloned the repository to a different directory. Fix: Replaced with Set-Location $PSScriptRoot — a PowerShell built-in variable that always resolves to the directory containing the script, regardless of the user or machine.

# Before (broken for other users)
Set-Location "C:\Users\adewusi.akeem\fintech-hub-spoke"

# After (works for anyone, anywhere)
Set-Location $PSScriptRoot

State Drift from Partial Applies

Multiple partial applies left orphaned Azure resources not tracked in Terraform state. Fix: Used terraform import for resources that existed in Azure but not state, deleted orphaned resources via Azure CLI, and performed clean destroy + apply.

Resource Group Destroy — Sentinel SecurityInsights Solution Blocking Deletion

During terraform destroy, Azure auto-creates a Microsoft.OperationsManagement/solutions/SecurityInsights resource not tracked in state, blocking resource group deletion. Fix: Added prevent_deletion_if_contains_resources = false to the azurerm provider features block.

provider "azurerm" {
  features {
    resource_group {
      prevent_deletion_if_contains_resources = false
    }
  }
}

🚀 Future Improvements

Priority 1 — Provider Upgrade

Upgrade azurerm Provider v3 → v4

azurerm v4.x includes improved ARM retry logic, VNet flow log support via target_resource_id, and better eventual-consistency handling. Eliminates time_sleep workarounds and the -parallelism=5 flag.

⚠️ Breaking changes: subnet policy values, deprecated arguments. Requires full destroy + redeploy.

Priority 2 — VNet Flow Logs

Enable VNet Flow Logs for Network Visibility

NSG flow logs were retired (blocked June 30, 2025). The replacement is VNet flow logs targeting the spoke VNet. Supported in azurerm v4.x or via the hashicorp/azapi provider using azapi_resource. Would populate AzureNetworkAnalytics_CL for Sentinel lateral movement detection.

Priority 3 — AzAPI Provider

Replace null_resource for Intune with AzAPI

The hashicorp/azapi provider calls any Azure/Graph API natively and tracks state properly. Replacing the null_resource Intune module enables drift detection — deleted compliance policies would be re-created on next terraform plan.

Priority 4 — Remote State

Terraform Remote State (Azure Storage Backend)

Currently state is stored locally. Production deployments should use an Azure Storage Account backend with state locking via Azure Blob lease.

backend "azurerm" {
  resource_group_name  = "rg-tfstate"
  storage_account_name = "stfintechtfstate"
  container_name       = "tfstate"
  key                  = "fintech.tfstate"
}
Priority 5 — Environments

Separate dev / staging / prod Environments

Use Terraform Workspaces or separate tfvars files. The var.environment variable is already threaded through all resource names, making this a low-effort extension.

Priority 6 — CI/CD

GitHub Actions / Azure DevOps Pipeline

Automate plan + apply via CI/CD. PRs trigger terraform plan posted as a comment; merges to main trigger terraform apply. Integrates with remote state backend for safe concurrent operations.

Priority 7 — Stress Test 2

Complete Conditional Access Bypass Test

Requires Entra ID Premium P1 license. Activate a 30-day free trial via Entra ID → Licenses → Try/Buy → Entra ID P2, enable the Compliant Device CA policy, and execute the test procedure documented in the Stress Tests section.

⚠️
Known Limitation — Intune null_resource: The Intune compliance policy is deployed via null_resource with a local-exec provisioner calling the Microsoft Graph API. While this successfully creates the policy in Intune, it does not support drift detection. The recommended fix is to migrate to the azapi provider (Priority 3 above).
